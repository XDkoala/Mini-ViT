# 阶段 7：MiniViT 基础消融实验

本阶段通过单变量实验分析 Patch Size、Encoder Depth 和数据增强如何影响 MiniViT 的准确率、泛化差距与训练成本。消融的目的不是盲目寻找最高分，而是用可重复证据解释各个设计选择的作用。

完成日期：2026-09-23

## 阶段概览

### 阶段目标

```text
固定 MiniViT baseline
  → 每次只改变一个因素
  → 独立配置与输出目录
  → smoke 排错
  → 正式训练
  → 比较准确率、泛化差距与耗时
  → 解释原因与限制
```

### 什么是消融实验

消融实验的核心是：**一次只改变一个研究变量，其余可控条件保持一致**。若同时改变 Patch Size、Depth 和学习率，即使结果变化，也无法判断究竟是哪一个因素造成的。

本阶段的基准条件是已经完成的 `EXP-001 MiniViT baseline`：

```text
patch_size = 4
depth = 6
augmentation = basic
seed = 42
epochs = 100
best val accuracy = 81.84%
```

基线已经提供三组实验各自的中间对照点，因此无需重复训练相同配置。

## 1. 实验矩阵

### 1.1 Patch Size

| Run | Patch | 图像 token | 相对基线改变 | 状态 |
|---|---:|---:|---|---|
| A1 | 2 | 256 | `patch_size: 2` | 已运行 |
| A2 / baseline | 4 | 64 | 无 | 已运行 |
| A3 | 8 | 16 | `patch_size: 8` | 已运行 |

CLS token 会额外增加一个 token，因此进入 Transformer 的总序列长度分别为 257、65 和 17。

需要观察：

- 更小 patch 是否因保留更多局部细节而提高准确率；
- token 增多是否显著增加单 epoch 时间和显存；
- 更大 patch 是否因压缩过强而损失细节。

Self-Attention 的注意力矩阵规模与 token 数平方相关。仅比较图像 token：

```text
patch 2：256² = 65,536
patch 4： 64² =  4,096
patch 8： 16² =    256
```

所以 patch 从 4 减到 2 时，图像 token 增加 4 倍，注意力矩阵元素约增加 16 倍；参数量变化却很小，因为共享的 Attention 参数不随 token 数增加。

### 1.2 Encoder Depth

| Run | Depth | 相对基线改变 | 状态 |
|---|---:|---|---|
| B1 | 3 | `depth: 3` | 已运行 |
| B2 / baseline | 6 | 无 | 已运行 |
| B3 | 9 | `depth: 9` | 已运行 |

需要观察：

- 更浅模型是否容量不足；
- 更深模型是否提高训练准确率却加重过拟合；
- 参数量和 epoch 时间是否近似随深度增长；
- 固定学习率下更深网络是否更难优化。

## 4. 实验前猜想

猜想提交日期：2026-09-22

记录边界：提交时 patch 8 已完成训练，但用户没有查看其实验结果，AI 也只做产物完整性盲验收、未读取或透露具体指标；depth 9、无增强和 patch 2 尚未完成。Depth 3 结果此前已经公开，因此 Depth 组不视为完全盲猜。以下内容在揭晓 patch 8 结果前固定，后续不根据结果反向修改。

### 4.1 Patch Size 猜想

> 我预测最佳验证准确率排序为：`p2 > p4 > p8`。
>
> 原因：CIFAR-10 只有 `32×32`，本来就丢失了很多细节，所以更应该采取小 patch，保留更细的局部结构。
>
> 我预测训练速度排序为：`p8 > p4 > p2`。
>
> 我认为更细粒度的视觉信息能抵消更大的过拟合风险，但会带来更高的计算成本。

这是一个可被实验推翻的明确预测：小 patch 的细节收益将超过额外优化难度和过拟合风险，代价则是更慢的训练速度。

### 4.2 Encoder Depth 猜想

> 我预测最佳验证准确率排序为：`d9 > d6 > d3`。
>
> 我预测 depth 9 的训练准确率会略有上升，但不会太多；泛化差距会更大。
>
> 原因：d9 太深了，而且样本不多，可能会背更多噪声，导致过拟合。

该预测认为额外深度仍会小幅提高最佳验证上限，但同时增加训练集记忆和过拟合；也就是说，预测“准确率最高”不等于预测“性价比最好”。

### 4.3 Data Augmentation 猜想

> 我预测无增强的训练准确率会更高，验证准确率会更低，泛化差距会更大。
>
> 原因：模型无增强会单纯地死背训练集，严重过拟合，训练准确率当然更高，验证准确率更低。

该预测把数据增强视为一种正则化：它会提高训练任务难度，却促使模型学习对位置移动和水平翻转更稳定的特征。

## 5. 运行策略

每份新配置先用独立 smoke 目录执行少量 batch，确认：

- 配置能正确创建模型和数据变换；
- 输入输出 shape、loss 和梯度正常；
- GPU 显存能够承受，尤其是 patch size 2；
- 正式输出目录不会被诊断运行污染。

smoke 只用于排错，不能与 100 epochs 正式结果混在同一张实验表中。正式实验仍使用完整训练集、验证集和 100 epochs。

### 5.1 配置与数据增强验收

`data.augmentation` 当前支持：

## 9. 三组消融总结

### 9.1 Patch Size

Patch 4 的验证准确率最高；Patch 2 保留更多细节但成本约为 baseline 的 3.81 倍且过拟合更明显；Patch 8 速度最快但信息压缩过强。当前任务的最佳平衡点是 patch 4。

### 9.2 Encoder Depth

准确率排序为 `d6 > d9 > d3`，三者只相差 0.68 个百分点。Depth 3 以约一半参数获得接近性能，效率最佳；Depth 9 增加约 50% 参数却无验证收益。当前任务不受益于继续加深到九层。

### 9.3 Data Augmentation

移除基础增强使训练准确率上升 2.74 个百分点，但最佳验证准确率下降 9.20 个百分点，最终泛化差距扩大 13.24 个百分点。RandomCrop 与 RandomHorizontalFlip 是首版 MiniViT 泛化能力的重要来源。

### 9.4 实验限制

- 每个配置只运行 seed 42，无法报告均值与标准差；
- 所有实验固定使用同一优化设置，不保证每个架构都处于各自最优条件；
- 结论限定于 CIFAR-10、32×32 输入和当前训练预算；
- 测试集仍未使用，阶段 7 的所有比较都基于验证集；
- Patch 2 的 epoch 59 计时受到系统睡眠污染，速度统计已显式排除。

## 10. 对实验前猜想的复盘

实验前猜想的意义不是展示“猜得准”，而是把当时的因果直觉明确写出来，再用数据检查其中哪些成立、哪些遗漏了重要因素。错误预测同样有价值，因为它能指出原有理解中过度简化的部分。

### 10.1 Patch Size：正确认识了细节与成本，但高估了细节收益

原预测：

```text
验证准确率：p2 > p4 > p8
训练速度：  p8 > p4 > p2
```

实际结果：

```text
验证准确率：p4 (81.84%) > p2 (80.02%) > p8 (77.30%)
训练速度：  p8 (10.03 s) > p4 (25.64 s) > p2 (97.72 s)
```

预测中正确的直觉有两点：

- CIFAR-10 分辨率低，过大的 patch 会进一步丢失局部结构，因此 p2 确实优于 p8；
- token 数增加会显著提高 Attention 计算量，速度排序完全正确。

偏差在于把“保留更多信息”近似理解成“验证准确率会单调提高”。Patch 2 不只保留细节，也把图像 token 从 64 增加到 256，使模型必须学习规模大得多的 token 关系。它最终训练准确率高于 p4，却有更大的泛化差距，说明额外容量更多地转化成了训练拟合，而没有完全转化为验证收益。

原先的说法“更细粒度信息能够抵消更大的过拟合风险”过于乐观，还遗漏了：

- 小数据是否足以约束更多 token 关系；
- 固定学习率和 100 epochs 是否适合更长序列；
- 细节中既有类别信息，也有噪声和偶然模式；
- 信息保留、优化难度、泛化和计算成本之间可能存在非单调权衡。

修正后的认识是：Patch Size 不是越小越好，而可能存在中间最优点。当前实验中 p4 在细节保留、训练难度和计算成本之间达到最佳平衡。

### 10.2 Encoder Depth：正确预判了过拟合方向，但混淆了容量与泛化收益

原预测：

```text
验证准确率：d9 > d6 > d3
d9 训练准确率：略微提高
d9 泛化差距：扩大
```

实际结果：

```text
验证准确率：d6 (81.84%) > d9 (81.46%) > d3 (81.16%)
d9 最终训练准确率：比 d6 高 1.02 pp
d9 最终泛化差距：比 d6 大 0.94 pp
```

“更深模型会略微提高训练拟合并扩大泛化差距”的判断成立，说明对模型容量和小数据过拟合的方向理解正确。未成立的是“额外容量仍会让 d9 的最佳验证准确率最高”。

这个偏差来自把两件事连接得过于直接：

```text
表达能力更强 ≠ 当前协议下泛化一定更好
```

更深网络只有在数据量、优化策略和正则化足以利用额外容量时，才可能带来稳定验证收益。当前 d9 多出约 50% 参数，训练准确率更高，却没有超过 d6；说明额外容量主要改善了训练集拟合，而非可迁移到验证集的规律。

修正后的认识是：深度与验证性能也可能呈倒 U 型。对当前 CIFAR-10 配置，d6 是准确率与成本的较好平衡，d3 则以近一半参数获得接近性能。由于只有一个随机种子，d6 与 d9 的 0.38 pp 差异不能解释为稳定的统计优势，严谨结论应是“没有观察到加深到九层的收益”。

### 10.3 Data Augmentation：方向全部正确，但机制表述需要更严谨

原预测：无增强会有更高训练准确率、更低验证准确率和更大的泛化差距，因为模型会“死背训练集”。三项方向全部得到实验支持，而且差异明显：

```text
最终训练准确率：no aug 97.94% > basic 95.20%
最佳验证准确率：no aug 72.64% < basic 81.84%
最终泛化差距：no aug 27.08 pp > basic 13.84 pp
```

正确之处是认识到增强会提高训练任务难度，同时发挥正则化作用。但“单纯死背”适合作为直觉，不够适合作为最终报告中的机制解释。无增强模型并非完全没有学习通用特征；更准确的说法是：它只反复观察固定像素布局，更容易利用训练集中的位置、方向和局部细节偶然性。

RandomCrop 与 RandomHorizontalFlip 让同一训练样本对应一组合理变体，相当于扩大经验训练分布，并把“轻微平移或水平翻转不应改变类别”的不变性加入训练。因此增强模型的训练准确率可能更低，却能在未见图片上更稳定。

这组实验还修正了只看 accuracy 的习惯：无增强实验的最低验证 loss 在 epoch 13，但最高验证 accuracy 到 epoch 94 才出现。模型后期可能偶尔多分对一些样本，同时对剩余错误样本变得极度自信；因此实验分析必须同时查看 accuracy、loss 和泛化差距。

### 10.4 对后续实验预测方式的改进

以后提出猜想时，应继续保留明确排序，同时增加以下内容：

- 分开预测训练拟合、验证泛化、参数量和速度，不能只猜一个准确率；
- 考虑非单调关系，例如“中等 Patch Size/Depth 可能最优”；
- 明确主要判据，本阶段是最高验证准确率，而不是最低验证 loss 或最终 epoch；
- 写出至少一个相反结果及其可能机制，避免只准备支持原观点的解释；
- 预先说明什么结果会推翻猜想；
- 对零点几个百分点的单 seed 差异保持克制，不把随机波动写成确定规律。

总体而言，这次预测并非简单的“对或错”：对计算复杂度、过拟合方向和增强作用的直觉较准确；主要需要修正的是把模型容量或信息保留与验证准确率作单调对应。实验最重要的收获，正是把这种直觉更新为“性能由信息、容量、优化、正则化和计算预算共同决定”。
